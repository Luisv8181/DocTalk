# DocTalk Web Product Specification

## Core interaction
The homepage should start with the user's context rather than the organization's taxonomy.

Suggested entry:
**I'm a...** Student / Resident / Physician / Fellow / Educator / Mental-health professional

Then:
**I'm looking for...** Immediate support / Someone to talk to / Professional care / Self-guided tools / Education / Research / Institutional change

Then:
**What are you dealing with?** Burnout / Anxiety / Depression / Sleep / Trauma / Grief / Suicide prevention / Substance use / Belonging / Difficult clinical experiences / AI & technology

Optional filters:
- location
- cost
- access method
- confidentiality/privacy
- evidence level
- language
- time commitment
- clinical vs educational

## Result card
Every card should show:
- resource name
- one-sentence purpose
- audience
- access
- cost
- geography
- evidence label
- review date
- privacy/confidentiality note where relevant
- emergency badge when applicable
- official source link
- limitations

## UX constraints
- No account required for core browsing.
- No collection of mental-health disclosures.
- Mobile-first.
- Keyboard accessible.
- Screen-reader friendly.
- High contrast.
- Reduced-motion support.
- Crisis resources cannot be buried beneath ordinary filters.
